# 源码布局与构建

本次贡献包含 Maclator 运行时、GPU 桥、应用入口、图标处理、Xcode 组件覆盖、回归测试，以及配套 MacFlow 源码。根目录仍是 Maclator 的 Cargo workspace；`integration/macflow` 是独立的嵌套 workspace，协议 crate 通过仓库内相对路径引用。不需要另一份位于仓库外的 MacFlow 检出目录。

运行时代码来自已冻结并验证的 GPR 写回实验源码，其源文件清单 SHA-256 为 `f17121721186238f4c8216fe6506550135b1d3a3501da4a8668524da04aa4339`。它保留已部署版的默认优化，并包含后续实验开关；后续实验仍默认关闭。新编译产物的路径和依赖布局不同，不能用旧安装产物的 SHA-256 代替这次构建验证，也不能声称所有实验共同开启时已通过验证。

MacFlow 使用同一冻结包中的配套协议和源码，保留已有运行时协议。另一个工作目录中后续独立改版的 MacFlow 界面没有覆盖此版本。GPU 屏幕呈现实验另附于实验贡献目录，根目录 GPU 桥保留已验证的基础实现。

## 构建

需要 x86_64 macOS、Apple Command Line Tools、Rust 1.99.0，以及实际运行 ARM 应用时所需的 ARM sysroot。仓库包含源码，不附带 Apple 系统文件、Xcode 组件、已签名应用、预编译运行时或本机配置。

```sh
cargo build --release -p maclator -j 2
cargo test --release -p maclator -p maclator-core -- --test-threads=1

cargo check --manifest-path integration/macflow/Cargo.toml --workspace
cargo test --manifest-path integration/macflow/Cargo.toml \
  --release -p macflow-core -p macflow-protocol

bash integration/build.sh
python3 integration/test_discovery.py
```

`integration/build.sh` 只在仓库中构建原生入口和 ARM 图标 shim，不执行安装。MacFlow 打包由 `integration/macflow/scripts/package.py` 完成；安装、服务注册、重启及回滚是显式操作，不由 Cargo 构建或本次贡献自动触发。

## 移植时调整

- Maclator 的 `macflow-protocol` 依赖改为 `../../integration/macflow/crates/protocol`，根 workspace 排除嵌套 workspace。
- MacFlow 部署脚本从新的嵌套目录定位 Maclator 根目录。
- XPC 回归测试在构建时要求显式 `--sysroot`；重跑已准备的测试使用记录中的路径。
- 开发用管理员测试脚本以 `--uid` 或 `SUDO_UID` 确定用户和所属组，不固定 UID 501 或 GID 20。它们需要实际安装的服务，不能作为普通单元测试自动运行。
- 文档和测试样例移除贡献者本机的绝对路径。

这些布局和开发脚本调整不修改运行时的指令语义或默认实验开关。性能、兼容性覆盖与未完成事项请参阅贡献总览和各实验记录；95% 原生性能目标尚未达到。
