# CPU 争用对照测试

这是验证工具，不是稳定性认证。它只比较一个原生 Rust 测试程序的主线程排队延迟，不能代表全局 FPS、实际输入到显示延迟、所有应用的流畅度或 Maclator 原生性能比例。

先构建及检查参数，不运行测试、不修改服务：

```sh
python3 scripts/compare_responsiveness.py --build-only
```

在已经安装、管理员助手已连接的 MacFlow 上，以当前登录用户运行：

```sh
python3 scripts/compare_responsiveness.py --output artifacts/responsiveness-comparison
```

默认九组对照，每组包含观察和控制两轮，并交替先后顺序。每轮创建一个独立的 30 线程、18 秒 CPU fixture；预热 12 秒，给连续两个五秒窗口及控制器续租留时间，然后运行三秒原生交互探针。fixture 自行结束，异常时脚本也会终止并回收自己创建的子进程。没有内存、磁盘或 GPU 压力负载。

脚本临时将模式设为自动、解除暂停、允许精确 fixture 路径后台管理。结束或收到中断时逐项恢复原来的模式、观察和暂停状态，并给测试路径添加保护规则。它不安装服务，不获取 root，不修改系统、EFI 或驱动；如果恢复失败，会在报告中明确列出。

每轮保存实际进程 nice、前后台身份、CPU、压力状态及租约数。控制轮必须实际出现 fixture nice 增加和活动租约，否则该对照无效，不能声称性能改善。每轮输出探针 p95、p99、排队时跳过的采样间隔以及固定时长 fixture 的实际完成工作量和校验值。

报告保留每组结果。20% p95 改善以及 50／100 ms 门槛分别判断；不存在用平均值掩盖失败场景的综合流畅度分数。后台代价由观测吞吐与控制吞吐的比值推算等工作量耗时增长，它不是实际应用固定工作量耗时测量。未测试的无争用退步、24 小时压力、七天日常稳定性及原生转译比例均标成未验证。

仅测试该 CPU 场景不足以满足整个发布门槛。保持同一供电、显示刷新率和日常工作负载；运行期间避免新增编译、备份等任务，以减少对照污染。
