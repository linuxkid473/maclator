# Signals and aligned 128-bit memory access

Maclator delivers guest-installed asynchronous Unix signal handlers at guest instruction boundaries. The host callback publishes a coalesced pending bit and an atomic siginfo record; it never locks the runtime or changes a live guest CPU. Each guest thread has its own pending state. Signals received by a host-only helper thread enter a process queue.

The ARM frame follows Darwin's siginfo/ucontext/mcontext layout. The guest's own libplatform trampoline receives the handler, style, signal, siginfo pointer, ucontext pointer, and a runtime validation token. Emulated sigreturn restores X0–X30, SP, PC, NZCV, all vector registers, FPCR/FPSR, alternate-stack status, and the signal mask; runtime helper pointers and JIT state remain owned by the current host thread. The sizes were checked against the installed SDK by compiling ARM static assertions (104/56/816 bytes). See Apple's [ARM XNU signal implementation](https://github.com/apple-oss-distributions/xnu/blob/main/bsd/dev/arm/unix_signal.c) and [libplatform trampoline](https://github.com/apple-oss-distributions/libplatform/blob/main/src/setjmp/generic/sigtramp.c).

The JIT instruction budget makes chained hot loops return to the dispatcher for delivery. Delivery is bounded in guest instructions, not wall-clock time: translating code or a blocked host syscall can extend latency. The interpreter checks at each instruction. Custom host callbacks omit SA_RESTART so interruptible host waits can reach guest execution; known read/write/receive/wait calls retry their SVC after guest sigreturn when SA_RESTART applies. Sleep, select, poll, kevent, sigsuspend, and unknown syscalls are not automatically restarted. Sigsuspend retains a one-shot delivery override because the host restores its original mask before returning EINTR.

The ARM regression fixture tests traditional delivery through SA_SIGINFO, explicit action masks and restoration, per-thread blocking/unblocking, sigsuspend, alternate-stack execution and EPERM while active, ucontext edits to GPR/vector state, nested SA_NODEFER, SA_RESETHAND, interrupted read and restarted read, pthread_kill to a worker thread, a timer interrupting a loop with no syscalls, and invalid syscall pointers. Each process group has a deadline; timed-out children are killed with the parent test process. Run `tests/check_guest_signals.py` with a runtime, compiled ARM guest, sysroot, and output directory; `--interp` selects the reference execution path.

Remaining signal limits are concrete:

- Synchronous hardware faults (SIGSEGV, SIGBUS, SIGILL, SIGFPE, SIGTRAP) retain their existing default/diagnostic handling. Guest registrations are recorded, but these handlers cannot recover faults until exact host-PC recovery is implemented.
- A process signal caught by a host-only helper is queued for a guest, but cannot reliably wake a guest blocked in a different host thread's syscall.
- Nonlocal exits from a handler, such as siglongjmp or setcontext, do not yet discard abandoned runtime frames. Repeated nonlocal exits can reach the 32-frame nesting limit; returning an older outer frame after abandoning an inner handler is unsupported.
- Mach exception ports, host launchd ARM XPC execution, and real-time signal queues are outside this delivery implementation.

Aligned 128-bit memory access uses one VEX.128 VMOVDQA load or store on Intel/AMD processors with OS-enabled AVX. This includes GPR64 and SIMD64 pairs, single Q-register access, and the interpreter's aligned 128-bit exclusive-load read. Reads support read-only mappings, unlike a CMPXCHG16B-based load that would require write permission. Unaligned and unsupported-host paths retain ordinary behavior. The eligible hardware's guarantee is described by [AMD APM Volume 2, section 7.3.2](https://docs.amd.com/api/khub/documents/sD1_QL~h4Afq2_tvzxqqSQ/content) and the Intel implementation rationale in [GCC's atomic-load change](https://gcc.gnu.org/pipermail/gcc-patches/2022-February/590960.html).

Maclator reports FEAT_LSE2 as absent in sysctl and the commpage. Aligned 128-bit support is narrower than the full feature: Arm requires atomicity for accesses within a 16-byte granule, including smaller unaligned accesses. See [Arm's architecture correction, section 2.130](https://documentation-service.arm.com/static/61fbeef72dd99944d05149a2). Statically compiled Apple-M1 code still benefits from the aligned pair implementation, while dynamic libraries avoid selecting broader LSE2 assumptions.

Core tests cover all 16 alignments, tagged addresses, complete write logging, and concurrent atomic-load versus CAS128 stress. Guest compatibility fixtures separately cover read-only pairs, aliases, writeback, and concurrent Apple-target 128-bit loads/stores. These tests establish the covered behaviors, not compatibility with every ARM application.

Final joint-candidate validation used runtime SHA-256 `65835d5f7c5cfd8a422baa00efb54285df277daa0749ed701bc427a2c5ce1cd2`. All 12 signal cases passed in JIT and interpreter execution with no timeouts; the runtime hash was unchanged after testing.
